# core

Up: [repository](../../../../AGENTS.md)

## What this is

The first code package of the monorepo rebuild. It holds the modules every layer needs and that import nothing else in the repository: where a venture's logical files sit, the venture's hash-chained provenance log, the instrumentation of calls, and one action's memo scope. They moved here from the old `schema` and `interface` folders, and now sit in `packages/naive/src/core/` (EE-118 step 5), so that the layers stop importing each other through them. Venture packages, which are records and not code, live in [`packages/naive/library/packages/`](../../library/packages/) (EE-116).

## Where things are

| Path | Holds |
|---|---|
| [`venture-paths.mjs`](./venture-paths.ts) | Where each logical file of a venture sits in its layout (`ventureFile`, `physical`, `logical`). The layouts are flat, structured (EE-086) and src (EE-118 step 8): in the src layout a package folder sits under the function that owns it (`PACKAGE_FUNCTION`, `srcPath`), so `foundation/problem.json` is at `src/strategy/foundation/problem.json` while its logical path stays the same. `it/` belongs to the it function (its connections, lead agents build plan item 7). It also maps the venture template's old path to `packages/naive/template/governance/` (`templatePath`). Imports nothing in the repository. |
| [`instrumentation.ts`](./instrumentation.ts) | Timing and measuring of each call and judgment, for agent vitals, and the venture's trace files (EE-121): `span`, `withSpan`, `currentSpan`, `spans`, `sessions` and `tracing` write and read `traces/<session>.jsonl`, one hash-chained span per line after the OpenTelemetry GenAI conventions, when the venture turns `traces` on in `naive.config.json`. Router calls and judgments become spans too. With traces off, `withSpan` runs its function outside any span, so no provenance line names a span that was never written. Imports `venture-paths.mjs`. |
| [`provenance.ts`](./provenance.ts) | The venture's append-only provenance log, `provenance.jsonl`, with its hash chain (EE-031). A line written inside a span names it in `span` (EE-121): an instrumentation span (`withSpan`), else the Effect span it runs in when NaiveTracer writes that span for this venture (`traceContextOf` in `effect/tracer.ts`). `effect/provenance.ts` offers the log as the `Provenance` service. A line is read, chained and appended inside a lock file beside the log (`.provenance.jsonl.lock`), so two processes writing at once cannot both chain onto one line. The logic is written as Effects (EE-125): files through `VentureFs`, failures as tagged errors, and the lock as a scoped resource (`lockFile`, with `Effect.acquireRelease`), so it is released however the work ends. Every export keeps its plain shape through `runSync`, because each router write calls `record` synchronously; the Effects are exported as `recordEffect`, `entriesEffect`, `recordGateEffect`, `readJsonlEffect`, `contentHashEffect`, `stealDeadLockEffect`, `takeStaleLockEffect` and `withLockFileEffect`. Before a line is appended, the bytes its `sha256` names go to the blob store (`blobs.ts`): the local file's bytes for a local write, the written content for a write to another source. A caller that passes only a `sha256` (a log route's append, a publish) stores no blob, so an append-only log does not keep a whole copy of itself per line. Imports the two above, `blobs.ts` and `effect/`. |
| [`blobs.ts`](./blobs.ts) | The blob store (the autoresearch design in everything-ecosystem, AUTORESEARCH_RECORDS_2026-11-06, "As-of reads"): `writeBlob`, `readBlob`, `hasBlob`, `blobFile` and `blobHash` (with `writeBlobEffect`, `readBlobEffect` and `hasBlobEffect`, the Effects behind them, EE-125) keep bytes under `<venture>/.naive/blobs/<aa>/<sha256>`, named by the same SHA-256 a provenance line records. A blob never changes: writing one that exists is a no-op, and a file that does not hash to its name is never served. The data model gives `.naive/blobs/**` the kind record, so a host commits it. It holds a copy of every version written through the router, private records included; the router never routes `.naive/`, so no route serves a blob. A `.mjs` file until core moves to TypeScript, which the compiled package allows (EE-159). Imports `venture-paths.mjs` and `effect/`. |
| [`sync.ts`](./sync.ts) | Syncing a system of record into a venture (EE-083): `sync(system, dir)` runs the command the app names in `NAIVE_SYNC_<SYSTEM>` (such as `NAIVE_SYNC_RHO`) with `--venture <dir>`, and `syncCommand` and `syncVariable` say which. Naive ships no sync command, so a system with none stays pointed. Hosted, the variable is ignored and every system stays pointed. create-venture and setup use it. Imports `runtime.ts`. |
| [`runtime.ts`](./runtime.ts) | Where Naive runs, and the one place that reads `NAIVE_RUNTIME`. Without it Naive runs as on a laptop and nothing here is consulted. With `NAIVE_RUNTIME=hosted` (`isHosted`), Naive reaches nothing outside the tenant: `envCommand` ignores `NAIVE_JUDGE_CMD` and the other command variables, and the host registers a function at start with `registerHook(name, fn)` for each thing it provides (`judge`, `site`, `trace`, `sandbox`, `git`, and `sql`, the host's effect/sql client for durable work on Postgres; `hostHook` reads one). A feature that needs a hook the host did not register throws a `HostedRefusal`, whose message names the feature and why. `git(feature, args, opts)` is `spawnSync("git", ...)` on a laptop; hosted it goes to the host's git working copy, or with none answers the way a missing git does, with the refusal in `error`. Imports nothing in the repository. |
| [`scripts.ts`](./scripts.ts) | `naiveScript(name)` finds a script by its file name across the units of `packages/naive/src/`, for code that runs another script as a child process; a `.ts` name also finds the `.mjs` the compiled package holds in its place, and a `.mjs` name finds the `.ts` a module became when it was converted (EE-159, EE-160). `PACKAGE_ROOT` is the folder whose `package.json` a venture installs: the code's root, or its parent when the code runs from `dist/`. Imports nothing in the repository. |
| [`action-scope.ts`](./action-scope.ts) | One action's scope: `actionScope`, `memo`, `forget`, `inAction` and `actionStats`, values computed once per router call and shared. Imports nothing in the repository. `packages/naive/src/engine/caching.ts` re-exports it. |
| [`signal-id.ts`](./signal-id.ts) | A signal's address (signal library design): `signalId` is the first 24 hex characters of the sha256 of the canonical JSON of every field but `id`, `canonicalJson` sorts keys at every level with no whitespace (the provenance log's rule), and `idHolds` says whether a signal's id is its address. Pure. Imports nothing in the repository. |
| [`crash-seam.ts`](./crash-seam.ts) | A test seam for crash-and-resume tests of durable work (EE-161): `crashSeam(name)` kills the process once when `NAIVE_DURABLE_KILL=<step name prefix>:<marker file>` names a matching step, right after the step ran and before its result is kept. Unset, it does nothing. The step bridge in `effect/durable.ts` and the trigger runner call it. Imports only `node:fs`, so the trigger runner can call it without loading Effect. |
| [`effect/`](./effect/README.md) | Naive's base for code written with Effect (EE-125): the tagged errors, `VentureFs` (the file system as a service, with an in-memory one for tests), the venture runtime (`ventureRuntime` and `VentureLayer`, EE-161) and the runners that let existing code call an Effect (`runSync`, `runPromise`, `runMain`). Imports only `effect` and Node built-ins. |

The old path `schema/venture-paths.mjs` re-exports `venture-paths.mjs` for one release, for an installed create-venture that imports it by path.

## Run and test

- `node packages/naive/src/checks/check-provenance.ts <dir>` checks a venture's provenance chain.
- `node packages/naive/src/interfaces/tests/as-of-test.ts` tests the blob store and as-of reads through the router.
- `node packages/naive/src/core/provenance-effect-test.ts` tests the provenance and blob Effects on a memory file system: the lock released however the work ends, the gate chain, and blobs stored and refused by hash.
- `node packages/naive/src/checks/check-traces.ts <dir>` checks a venture's trace files and the spans its provenance names.
- `node packages/naive/src/interfaces/test.ts` and `node packages/naive/src/interfaces/context-test.ts` cover these modules through the router. `node test.mjs` runs both.

## How it connects

- Called by: [`packages/naive/src/router/router.ts`](../router/router.ts), the CLI, the checkers in [`schema/`](../engine/README.md), the console bridge and the store kernel.
- Calls: only Node built-ins and the `effect` package (in `effect/`, `provenance.ts` and `blobs.ts`), and `provenance.ts` starts `packages/naive/src/router/orchestration/triggers.ts` as a child process after a write.
