# interfaces

Up: [src](../README.md)

## What this is

The ways a person, or an agent, works with a venture: the `naive` and `mentura` CLIs, the MCP server and the local HTTP API, all over one router (EE-030). Also the skills the Claude Code plugin ships, the harness adapters, the agent harness and the operator console.

- `node packages/naive/src/interfaces/test.ts` tests the router and the three interfaces over it.
- `node packages/naive/src/interfaces/plugin-test.ts` tests the plugin manifest and skills.

## How it connects

- Calls: [`router`](../router/router.ts).

`naive dev` checks each record as it is saved with `validateFile` from [`packages/naive/src/records/validate.ts`](../records/README.md), and `naive info` no longer reports a Python version, because nothing here needs one.

`naive upgrade --framework` moves a git pin (`git+https://...#<sha>`, which create-venture writes from a clone) to the commit of the Naive running it and installs from that clone with `npm install --no-save`, so the update needs no network. The clone is `PACKAGE_ROOT` from [`core/scripts.mjs`](../core/scripts.ts), the folder above `dist/` when the CLI runs compiled (EE-159).

`naive copy gaps|draft|check|one-shot` (EE-216) is dispatched from `cli/naive.ts` to [`copy.ts`](../functions/marketing-and-sales/marketing/copy.ts): a public page's words are `marketing-message` records a person approves before any design is built.

## Writes from the interfaces

The discovery harness (`harness/run.ts`, `harness/site.ts`) and `cli/naive.ts` write a venture's records through `packages/naive/src/store/record-write.ts`, which checks each against its schema and logs it. What they still write directly (the agent's MCP config, the run trace, generated type files) is listed with its reason in `packages/naive/src/checks/direct-writes.json`.

## naive check

`naive check` runs every checker in [`../checks/`](../checks/README.md) that reads a venture folder, on the venture you are in. A checker of Naive's own files (the data model, the nouns, the docs) is not run here: `node test.ts` runs those. A checker a venture names under `checks.off` in `naive.config.json`, by its path (`packages/naive/src/checks/check-telos.ts`), is skipped and shown as off. One under `checks.warn` is run and reported and does not fail the command. `tests/naive-cli-test.ts` fails when a checker that reads a venture is added to the folder and left out of the command.

`naive runs [verify <run>]` and `naive workflow run <function>/<workflow>` (EE-227) are dispatched from `cli/naive.ts` to [`run-proof.ts`](../engine/run-proof.ts) and [`workflow-run.ts`](../engine/workflow-run.ts): every run's package checked against the provenance log and the blob store, and a workflow run step by step with each step's evidence gathered by its session. `naive check` runs `check-runs`. The lead skill ([`skills/lead/SKILL.md`](./skills/lead/SKILL.md)) verifies run packages, never an agent's say-so.
