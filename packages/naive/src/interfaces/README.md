# interfaces

Up: [src](../README.md)

## What this is

The ways a person, or an agent, works with a venture: the `naive` and `mentura` CLIs, the MCP server and the local HTTP API, all over one router (EE-030). Also the skills the Claude Code plugin ships, the harness adapters, the agent harness and the operator console.

through the routes their workflows write and read, with the evidence, and the routes read that no workflow writes or written that none reads; `--mermaid` prints the feeds between functions (EE-188). `naive effects [<element>] [--at <iso>] [--json]` runs [`element-effects.ts`](../engine/element-effects.ts) on the venture: each element's state, capability level and why, the harm and caps it takes from the elements that feed it, and for one element what happens downstream if it were absent, weak or strong (EE-190). `naive agent list|brief|run` runs [`agents/run.ts`](../engine/agents/run.ts): run hands a role's prompt to `NAIVE_AGENT_CMD` as that role, or prints it. `mentura` stays as an alias. `mentura <route> write --as person --revert` marks a write as restoring the version before (provenance activity `rollback`), which resolves the gate's no call on the reverted write as a miss when the venture keeps the gate detector. `naive trace append` and `naive trace show` run [`trace-cli.ts`](../engine/trace-cli.ts) on the venture's trace files (EE-121). `naive activities list|propose` run [`activity-proposals.ts`](../engine/activity-proposals.ts): what the activity catalog's scores propose for the venture's functions, filed as open decisions by `propose` (EE-169). `naive signals emit|pull|explain|replay` run the signal library's [`orchestration/signals.ts`](../router/orchestration/signals.ts) on the venture (signal library build item 5). `naive recipes init`, `naive recipes plan` and `naive recipes check` run [`recipes/cli.ts`](../engine/recipes/cli.ts): a person's starter recipe, a person's eval plan, and training feedback on it. `naive recipes search <pattern>` runs [`orchestration/recipe-search.ts`](../router/orchestration/recipe-search.ts): a knob descent with no model, each step written through the recipe route, so a keep is held for a person. `mentura accept recipes/<pattern>` sends a recipe's held tip to its route's `accept`, which runs the holdout check, instead of moving a draft into place. `mentura operations/handoff/<id> claim --venture <id>` takes a ready, unclaimed handoff for the acting role once, through the router's [`handoff-claim.ts`](../router/handoff-claim.ts); `claimed_by` is `MENTURA_SESSION`, else the role. `mentura index` also returns the decision queue across functions (`queue`, EE-127). `naive handoff run <id>` runs a handoff's done-criteria, as a durable workflow when `durable.engine` is set ([`durable-handoff.ts`](../router/orchestration/durable-handoff.ts)) and through `run-handoff.ts` otherwise. `naive run <file>` runs a venture program on the venture runtime ([`venture-program.ts`](../engine/venture-program.ts), EE-161). `naive sync link <business>`, `naive sync pull`, `naive sync push` and `naive sync status` run [`sync.ts`](../engine/sync.ts) on the venture: the device sign-in, the store's changes merged into the files, this copy's changes sent with their base versions, and where the copy stands with no network (EE-178). `naive dev` starts each server before it prints or uses its address, so no other process takes a port between a probe and the listen. `naive check` also checks the venture's Effect pin and that it resolves the same version of Effect as Naive ([`effect-pin.ts`](../engine/effect-pin.ts), EE-161). `naive activities defaults [--function <id>] [--json]` lists the activities a person performs by default for their kind (EE-179). `naive activities briefing [--venture <dir>] [--function <id>] [--json]` prints what each function's APQC process groups need from a person (EE-180), and `mentura operations/activity-briefing run --venture <id>` returns the same as JSON through the router, with one route per function (`operations/activity-briefing/<function>`). Both CLIs call `blockingStdio()` from [`core/stdio.ts`](../core/stdio.ts) first, so output to a pipe is whole before the process exits. The CLI parses a route action's `--input` file once, before the route runs. When the file is not JSON, the command exits 2 with one line naming the file and the parse error. The command writes no provenance line. |

## Run and test

- `node packages/naive/src/interfaces/test.ts` tests the router and the three interfaces over it.
- `node packages/naive/src/interfaces/plugin-test.ts` tests the plugin manifest and skills.

## How it connects

- Calls: [`router`](../router/router.ts).

`naive dev` checks each record as it is saved with `validateFile` from [`packages/naive/src/records/validate.ts`](../records/README.md), and `naive info` no longer reports a Python version, because nothing here needs one.

`naive upgrade --framework` moves a git pin (`git+https://...#<sha>`, which create-venture writes from a clone) to the commit of the Naive running it and installs from that clone with `npm install --no-save`, so the update needs no network. The clone is `PACKAGE_ROOT` from [`core/scripts.mjs`](../core/scripts.ts), the folder above `dist/` when the CLI runs compiled (EE-159).
