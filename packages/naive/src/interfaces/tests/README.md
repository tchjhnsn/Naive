# tests

Up: [repository](../../../../../AGENTS.md)

## What this is

Tests that run a module in `packages/naive/src/engine/` through the router: its route via `call`, the MCP server or the HTTP API. They moved here from the old `schema` folder in the monorepo rebuild (router inversion, step 2), because a test that runs a route tests the router and the module together, so it sits above both. That way the engine does not import the router for its tests. The design is [`docs/design/MONOREPO_ROUTER_INVERSION_2026-11-05.md`](../../../../../docs/design/MONOREPO_ROUTER_INVERSION_2026-11-05.md).

## Run and test

- `node packages/naive/src/interfaces/tests/<name>-test.mjs` runs one test. Each prints its checks and exits 1 on a failure.
- `node test.ts` runs all of them.

## How it connects

- Calls: [`packages/naive/src/router/router.ts`](../../router/router.ts), the MCP server and the HTTP API, and the `schema/` modules under test. A test that reads the data model or a schema reads it through [`packages/naive/src/records`](../../records/README.md), as `freshness-test.ts` does.
- `setup-test.ts` points finance at rho with `NAIVE_SYNC_RHO` naming the stand-in `packages/naive/src/records/examples/money-sync/sync.ts`.
- `setup-test.ts` and `delegation-test.ts` run create-venture from [`packages/create-venture/`](../../../../create-venture/index.mjs), where it moved from the interface folder in step 2 of the Naive layout (EE-118).
- A test in `schema/` that does not import the router, the MCP server, the HTTP API or a module in [`packages/naive/src/router/orchestration/`](../../router/orchestration/README.md) stays next to its module, even when it starts the CLI as a child process.

Tests that check a record against its schema run `node packages/naive/src/records/validate.ts`, not Python.

`decision-index-test.ts` also checks `ownScore` on fail-closed decisions due in five and fourteen days: a nearer due date scores higher, and failing closed adds weight (naive#72). It also checks that a one-way door, by `door` or by class, ranks above every framework placeholder and says why.

`hosted-runtime-test.ts` also runs an effect done-criterion (`runs: "effect"`) hosted with no sandbox hook: it runs on the venture runtime, so it needs none (EE-161).

`durable-handoff-test.ts` kills a durable handoff run inside its second criterion (the criterion kills its own process) and checks that the next run resumes without rerunning the first, writes one evidence file through the router with provenance, and that `naive handoff run` uses run-handoff.ts with the memory engine (EE-161). It also runs a handoff hosted on `durable.engine` postgres through a `sql` hook, and checks the refusal without one.

`recipe-search-test.ts` also kills a durable search right after its first experiment write lands and checks that the next run resumes, writes no step twice and ends at the plain search's tip (EE-161).

`durable-triggers-test.ts` kills the trigger runner right after a trigger's route call lands and before the run is saved, and checks that the next run finds the call in provenance by its key (trigger and event), records the run as ran without calling the route again, and that the chain holds (EE-161, phase 12d).

`durable-signals-test.ts` kills a durable signal pull right after its first record write lands and checks that the next run resumes, writes each projected record once with one provenance line, keeps the chain, moves the cursor, and that a pull after it writes nothing (EE-161).
