# Schema index

Code reads the schema files and `packages/naive/src/records/data-model.json` through the record types' resolver, [`packages/naive/src/records`](../records/README.md), never by building the path from the folder name; `node packages/naive/src/checks/check-record-paths.ts` fails when it does. The files themselves stay here until step 5a-2 of the monorepo rebuild (design in pull request #243) moves them. A test that builds a copy of the repository points the resolver at it with `recordsIn(copy)`.

Where a venture's logical files sit (`ventureFile`, `physical`) moved to [`packages/naive/src/core/venture-paths.mjs`](../core/venture-paths.mjs) in the monorepo rebuild; `schema/venture-paths.mjs` re-exports it for code outside this repository.

The route table that modules here read (`routes`, `resolve`, `glob`, `files`, `gateOf`) is [`packages/naive/src/records/routes/routes.mjs`](../records/routes/routes.mjs); import it from there, not from `packages/naive/src/router/router.mjs`. The command routes of the brand, the lint suites and the cache are data in [`packages/naive/src/records/routes/commands.mjs`](../records/routes/commands.mjs), and the per-action memo is [`packages/naive/src/core/action-scope.mjs`](../core/action-scope.mjs); `brand.mjs`, the `lint-*.mjs` modules and `caching.mjs` re-export them.

Tests that run a module here through a route (the router's `call`, the MCP server or the HTTP API) live in [`packages/naive/src/interfaces/tests/`](../interfaces/tests/README.md), because they test the router and the module together. A test that does not import the router, the MCP server or the HTTP API stays next to its module, even when it starts the CLI as a child process. The modules that compose routes (triggers, setup, migrate, releases and model steps) are in [`packages/naive/src/router/orchestration/`](../router/orchestration/README.md). Nothing here imports the interface: `release-card.mjs` draws the release card for `start-release.mjs`, and `adapters.mjs` writes adapter files for an upgrade, while verifying an adapter stays in `packages/naive/src/interfaces/adapters.mjs`. Nothing here imports `scripts/` or `operations/` either: `transcripts.mjs` reads agent session transcripts for `activity.mjs` and the diagnosis script, and `check-public.mjs` is the public gate for marketing content (route `operations/marketing/public`) that `publish-lint.mjs` runs. `packages.mjs` does not import the idea map in `packages/naive/src/functions/strategy/frameworks/idea-map/`: the idea map's routing is passed in, and [`packages/naive/src/router/orchestration/venture-package.mjs`](../router/orchestration/venture-package.mjs) composes the two. No unit imports another in a cycle (`node scripts/dependency-rules.ts`).

Adapters (`packages/naive/src/engine/adapters.mjs`, Z-4) are the harness adapters in `packages/naive/src/interfaces/adapters/` plus the platform adapter an app names in `NAIVE_PLATFORM_ADAPTER`. `node packages/naive/src/interfaces/adapters.mjs verify` runs the tests a platform adapter lists: an absolute path, a path relative to the adapter file's folder (the app's own test, run from that folder), or a framework test in this repository.

The Everything Ecosystem is a schema, version in `VERSION`. An instance is a builder's workspace: a set of ventures, each with its product cards and, where it keeps them, account records (EE-011, EE-021). Personal life is out of scope (EE-009). This index lists every record type, so anyone can build an instance from this repo alone. Its machine form is `packages/naive/src/records/data-model.json` (EE-018): every record type, its owning layer, schema, paths and references, checked by `packages/naive/src/checks/check-data-model.mjs`. There is no single master schema; the data model is the map of all of them. Nouns follow `packages/naive/src/terms/ontology.md` (EE-014).

Status:
- **defined**: a JSON Schema exists.
- **prose**: the shape is described only in Markdown.
- **missing**: the record type has no definition yet.

Hosted mode (`NAIVE_RUNTIME=hosted`, [`packages/naive/src/core/runtime.mjs`](../core/runtime.mjs)) changes these modules and nothing on a laptop. The judge in `caching.mjs` and `frames.mjs` asks the host's `judge` hook and refuses without one. `run-handoff.mjs` sends each bash done-criterion to the host's `sandbox` hook and refuses without one; it also exports `runHandoff(dir, id, opts)`, and without a git working copy its evidence names the package version (`naive-framework@<version>`). `activity.mjs` refuses to read a transcript folder outside the venture, such as `~/.claude/projects`. `venture-type.mjs` refuses to classify. Git goes through `git()` in core: `updateFramework` in `upgrades.mjs` and planning a port of a git repository in `port-venture.mjs` refuse without the host's `git` hook, and where git only adds something (a tracked move in `upgrades.mjs` and the layout migrations, first-seen dates in `time-to-ready.mjs`) a refused call acts as a folder with no git. `port-venture.mjs` ships its trace through the host's `trace` hook in place of `NAIVE_TRACE_CMD`.

## Docs next to the code

Every README in this repo, this one included, and every playbook under `packages/naive/library/packages/*/playbooks/` is checked by `packages/naive/src/checks/check-docs-claims.mjs`: the paths, commands and routes it names must exist and its relative Markdown links, inline or reference-style, must resolve (HTML `href` and `src` are not checked). A pull request that changes code here, meaning any file that is not `.md` or `.mdx` and not under a `playbooks/` folder, owes this README an update, or a line in its body that starts with `No docs change: ` and gives a real reason (`.github/workflows/docs-required.yml`). New READMEs follow `docs/readme-template.md`.

The pure signal render (signal library build plan item 3) has its own README: [`packages/naive/src/engine/signals/`](./signals/README.md). It turns signals into records with no I/O and no clock: views of a signal and its parts, salient or noise at each listener, withdrawal, the six reducers, a render to a fixpoint and a diff. The folder is private: only it and the signal engine beside it may import it (`scripts/dependency-rules.ts`).

The recipe sandbox (autoresearch build plan item 4) and the eval sets and scoring (item 5) have their own README: [`packages/naive/src/engine/recipes/`](./recipes/README.md). The sandbox lints a venture recipe, runs a batch of calls in one child process under Node's permission model with a fresh `vm` realm per call, and checks that the receptions cover each heard signal once. It is layered defence, not a security boundary; QuickJS compiled to wasm is the hardening path (not built). `naive recipes plan` freezes an eval set from what people and producers settled, and `naive recipes check` and the dev verdict score a recipe on it.

`workspace-init.mjs`, `workspace-init-test.mjs` and `frames-test.mjs` run create-venture from [`packages/create-venture/index.mjs`](../../../create-venture/index.mjs). It moved there from the interface folder in step 2 of the Naive layout (EE-118). Not built yet: Naive as one package, the rest of that layout.

## Open reconciliations

1. **Venture profile guidance.** The profile has no guidance of its own since the SAD documents were removed (EE-036); write a short template when a venture first needs one.
2. **MAD's tiers.** EE-013 renames MAD's four layers to tiers; the MAD repo and older method documents still say layers.
3. **Decisions.** The schema keeps its own log (EE-001 to EE-017). Older documents under `operations/` still cite workspace ids.
4. **Personal references.** About twelve files still name one person or their paths. They need to be made generic or moved out.
5. **Personal system.** Out of scope (EE-009). Built separately and joined later through links.
6. **Layer.** The term engine admits layer in its standard technical sense: a part of an arrangement whose dependencies hold no cycle and put every part in one stack, so each part depends only on the parts beneath it. Run on real arrangements, it passes the OSI model and the ontology's three layers (metamodel, upper ontology, catalog). It fails Naive's own groupings, both the seven EE-001 decided (their loop is a cycle) and the seven manifests as built (their reads form cycles, such as knowledge reading venture from system while system reads decision from knowledge). So for Naive's groupings "layer" works as the system's name for its parts, and the general word keeps its standard meaning with no definition of Naive's own. EE-013 ("layer means only the system's seven layers") and the `layer` noun in `packages/naive/src/terms/ontology.json` ("one of the six") are unchanged; reconciling them is Torian's call.

The engine's modules (decisions, freshness, generators, lifecycle, upgrades, user frameworks, workspace) validate a record in process with `validateFile` or `validateValue` from [`packages/naive/src/records/validate.mjs`](../records/README.md). None of them starts Python.
