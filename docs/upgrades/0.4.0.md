# Upgrading to Naive 0.4.0

Naive 0.4.0 runs every venture on Effect (EE-161). Naive declares `effect` as a peer dependency at one exact version, and the venture's `package.json` pins the same version, so Naive and the venture's own programs load one copy and agree on every service. Run `naive upgrade <venture dir>`; the `effect-pin` migration writes the pin.

## What the upgrade does

- Pins `effect` under `dependencies` in the venture's `package.json`, at the exact version Naive declares. A pin under `devDependencies` moves to `dependencies`. A venture with no `package.json` runs on Naive's copy and is left alone.
- On every later upgrade, moves the pin again when the installed Naive declares another version, so the two always move together.
- Logs the change in provenance as written by `naive-upgrade`.

Then install (`npm install`), so the new pin is what loads.

## Checking it

`naive check` reports `effect`: it fails when the pin differs from Naive's, and when the venture loads a different version of Effect from the one Naive loads. Reinstall to fix the second. Two installs at the same version, as when Naive is linked from a clone, pass: Effect keys its services by name, so they interoperate.

## By hand

- If the venture has its own programs that import `effect`, run `npm install` after the upgrade so they load the pinned copy.
- If another dependency of the venture pins a different `effect`, align it, or `naive check` will report two versions.
