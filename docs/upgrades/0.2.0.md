# Upgrading to Naive 0.2.0

Naive 0.2.0 moves a venture's records out of the layer folders and into package folders (EE-070). Run `naive upgrade <venture dir>`; the `package-layout` migration does the moves.

## What the migration does

- Moves the foundation records: `purpose/validation/problem.json` to `foundation/problem.json`, `purpose/icp.json` to `foundation/icp.json`, `purpose/alignment.json` to `foundation/alignment.json`, and `purpose/telos.draft.md` to `foundation/telos.draft.md`.
- Moves validation records to `validation/`, the team plan to `people/team-plan.json`, product cards from `products/` to `product/`, and Product Anatomy files to `product/anatomy/`.
- Moves decision files from `purpose/decisions/`, `purpose/anatomy/decisions/` and `operations/decisions/` into `decisions/`. Each one is stamped with the path of the record it decides first, so it still decides the same record.
- Moves the brand pillar to `marketing/brand.md` and rewrites the publication policy to point there.
- Creates the data folders a package venture has: `raw/dump`, `raw/sources`, `ideas`, `finance`, `customers`, `investors`, `money` and `public`.
- Writes `.release/layout.json` with every move.

Files move with `git mv` when git tracks them. Each move is a new provenance line.

## What it escalates

The product and business pillars, and anything under `purpose/research/`, have no package home. The migration archives them under `_private/` and lists them for you. Decide where each belongs and move it yourself; nothing is guessed.

## Old routes

Every old route keeps working through `interface/route-aliases.json`. A read on `purpose/validation/problem` answers from `foundation/problem` with a note that the old name is deprecated. Agents that still use the old routes keep working for one release.

## By hand

- If you wrote your own scripts against the old paths, change them to the new ones.
- Check `_private/` for what was archived and decide where it goes.
