# Upgrading to Naive 0.3.0

Naive 0.3.0 settles two words (EE-071). A package is Naive's open definition: schemas, templates and checks. A kit is Mentura's enhanced package: automations, agent workflows, skills and connectors. Run `naive upgrade <venture dir>`; the `kit-to-package` migration does the rewriting, and the upgrade pins your versions.

## What the upgrade does

- Pins the framework in `naive.config.json` (`naive.version`, `naive.channel`) and every package the venture uses (`packages`). A venture with no pin is treated as Naive 0.1.0.
- Moves each name in `naive.config.json` `kits` that is a Naive package into `packages`. A Mentura kit stays in `kits`. Any other name is escalated, never guessed.
- Rewrites routes inside records from layer and kit routes to package routes, through the route aliases: the routes a decision unlocks, the routes each team-plan role may read and write, and the parent route of each where-used fact. For example, `purpose/validation/solution` becomes `validation/solution` and `purpose/product/*` becomes `product/*`, so locks and access keep meaning what they meant.
- Escalates a route glob that spans routes now in several packages, such as `purpose/**`. Rewrite it yourself.
- Writes `.release/upgrade-0.3.0.json` and refreshes any adapter files installed in the venture.

Rewritten records are logged as written by `naive-upgrade`, an agent, so a record a person had confirmed shows as needing review again.

## Channels and early packages

- `--canary` puts the venture on the canary channel, where experimental packages (legal, operations, relationships, counsel) can be adopted. `--stable` goes back once none is adopted.
- `--adopt <package>` opens a later phase's package now. It is pinned with `"early": true` and the venture package lists it as open. `--drop <package>` undoes it.

## By hand

- In your own `AGENTS.md` files, say package where you wrote kit for one of Naive's packages. A kit is only Mentura's now.
- If a script reads `naive.config.json` `kits` as a list of packages, read `packages` instead.
- Review the records the migration rewrote, listed in `.release/upgrade-0.3.0.json`.
