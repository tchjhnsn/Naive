The program is `node packages/naive/src/interfaces/cli/mentura.ts`, run from the repository root. The workspace is `MENTURA_WORKSPACE`, else `--workspace`, else the current directory. To print this syntax from the code:

```sh
node packages/naive/src/interfaces/cli/mentura.ts help
```

## Syntax

The block below is the program's own usage text. It is syntax, not a shell script.

```text
node packages/naive/src/interfaces/cli/mentura.ts routes [--group <phase>] [--json]
node packages/naive/src/interfaces/cli/mentura.ts groups [--json]
node packages/naive/src/interfaces/cli/mentura.ts ventures [--json]
node packages/naive/src/interfaces/cli/mentura.ts init <dir> --id <id> [--phase <phase>] [--layers purpose,governance]
node packages/naive/src/interfaces/cli/mentura.ts upgrade --venture <id>
node packages/naive/src/interfaces/cli/mentura.ts add <department> --venture <id> [--group]
node packages/naive/src/interfaces/cli/mentura.ts accept <route> --venture <id> [--confirm <route>]
node packages/naive/src/interfaces/cli/mentura.ts confirm <statement> --venture <id> [--confirm <statement>]
node packages/naive/src/interfaces/cli/mentura.ts <route> <action> --venture <id|path> [--input <file>|-] [--as person] [--value <n>] [--json]
node packages/naive/src/interfaces/cli/mentura.ts baseline --venture <id>
```

Actions are `read`, `write`, `check`, `template`, `layout`, `view`, and `run` for commands. A write takes `--derived-from`, `--decision` and `--note`. `template` and `layout` may omit `--venture`.

`init` creates new ventures only. Like `create-next-app`, it refuses a directory that exists and is not empty, so it never writes over your files (EE-076).

## The framework commands

`node packages/naive/src/interfaces/cli/naive.ts` is Naive's own program. `mentura typegen` and `mentura upgrade` run the same commands.

```text
node packages/naive/src/interfaces/cli/naive.ts typegen
node packages/naive/src/interfaces/cli/naive.ts upgrade <venture dir>
node packages/naive/src/interfaces/cli/naive.ts port --from <project> --venture <dir>
node packages/naive/src/interfaces/cli/naive.ts port --venture <dir> --apply --confirm port
node packages/naive/src/interfaces/cli/naive.ts migrate --from <project> --venture <dir>
node packages/naive/src/interfaces/cli/naive.ts migrate --venture <dir> --apply
```

- `typegen` writes `.naive/types/` from the route table and the MCP tools.
- `upgrade` moves a venture onto the next Naive layout, the way `next upgrade` does for a Next.js app. It was called `migrate` until 2026-10-29, and `mentura migrate --venture <id>` without `--from` still runs it for one release, with a notice.
- `port` moves an existing folder into a venture as it is (EE-076). The folder is moved whole with a rename, so no file in it is opened or changed, and a git repository keeps its history and uncommitted work. `naive port <folder>` adds the move to a plan at `<venture>/.release/port-plan.json` and moves nothing: the folder goes to `repo/<its name>` unless `--to` says where. Run it once per folder. The plan says what the move would break: worktrees of the repository, symbolic links that point into the folder, and processes working inside it. You can set any item's action to `leave` before you run `--apply --confirm port`. Applying never overwrites, never copies across disks, refuses a folder that is not the one planned, refuses while a process works inside it unless `--even-if-busy`, names each folder in `sources.json` as a read-only source of truth, and records each move in `provenance.jsonl` with the path it came from.

- `migrate` is the other way in. It rewrites the project into Naive's conventions rather than keeping its files. An agent reads the project's text files and proposes records in the shape of Naive's schemas. The agent is `claude -p` with no tools, or the command in `MENTURA_AGENT_CMD`. The plan goes to `<venture>/.release/migrate-plan.json`, and migrate proposes one open decision per function, such as `migrate-product`. Nothing is written until you decide each one with `mentura decide`, answering "bring in", "point to them" or "leave them". `--apply` then writes each record through the router, so its schema, gates and provenance apply. Every record names the decision and the file it came from.

- `node packages/naive/src/functions/marketing-and-sales/marketing/publish-build.ts <channel> <venture dir> [--out <dir>]` builds the site's own outputs through the publishing gate (EE-064), and a publish reads only what it writes. `site` writes `generated/venture-facts.json`, which the marketing pages' `Fact` reads. `artifact` also writes the one-page marketing artifact, `artifact/index.html`. `foundation` writes the strategic foundation one-pager, `artifact/foundation.html`. Everything goes under `site/` unless `--out` names another folder. The build stops at the first failure. First, `packages/naive/src/engine/check-public.ts` checks each public variant in `operations/marketing/content/`: it must name its source as `variant_of: <record>#<field>`, its audience and, when published, its approver, and it must not copy ten words of its source. Then each field reaches the output only through `publicValue` in `packages/naive/src/engine/visibility.ts`: the field itself when a person approved its wording as public, or its approved MDX variant. Then the output is checked for any internal field's own wording and for anything `packages/naive/src/engine/check-leaks.ts` matches. Last, `generated/publish-build.<channel>.json` records each output's sha256, the approved variants it drew on, and the drafts still waiting for a person.

- `naive lint premises [<route>] [--drafts] [--json] [--propose]` asks hard questions of a venture's own goals, requirements, exit criteria, constraints and decisions, and never edits them. Each rule in `naive.config.json` under `premise_lint.rules` is `off`, `warn` or `error`, and any error-level finding exits 1. `--propose` files each finding as an open decision for a person to answer, once: rerunning files nothing new and never reopens a decided one. It reads decisions the way `decisions.mjs` does, so nothing under a `_` folder such as `_private/` is ever read. The linter skips the decisions it drafted itself. A proposal that fails prints why and exits 1.

Port and migrate only read the project. Files that look like secrets (`.env`, keys, `id_rsa`, `credentials.json` and similar) are never opened. Port is cheaper and keeps your files exactly. Migrate fits Naive better, but costs an agent pass and more decisions. `mentura migrate --from <project> --venture <id>` is the same command as `naive migrate`.
