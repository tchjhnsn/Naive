# lean/

Proofs that settle Naive's definitions. When a term is contested (is this person a founder? is every co-founder a founder?), the answer comes from running a check or a proof, not from asking someone how it was defined.

- `Naive/Concept.lean`: the engine. A concept is a list of named, decidable properties; `passes`, `failed` (why not), `IsA`, `Disjoint`, and `refine_isA` (adding properties narrows a concept).
- `Naive/Terms.lean`: the relation is total (R3); every phase gate is a threshold guardian; admitting a term keeps term ids unique, and by induction any sequence of admissions does (§23).
- `Naive/Founder.lean`: founder (P7, F1 to F5) and co-founder. Proves every co-founder is a founder, unconfirmed facts never make a founder, and an unevidenced contribution never counts. `decide` settles single cases.
- `Naive/Layer.lean`: layer in the technical sense. An order that every dependency points down rules out a cycle (`downward_order_no_cycle`), so a cycle rules out every such order (`cycle_no_downward_order`), and EE-001's five looping groupings have none (`ee001_loop_no_downward_order`). A witness shows the ontology's three have one.
- [`Naive/Generated/Ontology.lean`](./Naive/Generated/Ontology.lean): generated, never edited by hand. `node schema/terms/gen-concepts.ts` writes one concept per noun in [`docs/ontology.json`](../docs/ontology.json) (EE-014), inside `namespace Ontology`. The ontology records a noun's meaning as prose and its placement as data, so each concept's properties check placement only: `level <level>` always, and `function <id>` when the noun names a function. The facts are `Placement` (a level and an optional function), with no label field. Two nouns with the same placement pass the same facts, so these concepts can prove two nouns apart only by placement (the two senses of customer, `customer_finance` and `customer_marketingAndSales`, are disjoint); telling nouns apart by meaning takes an admitted term. The file's header states that limit. The noun, meaning, standard and status sit in each docstring, followed by every other field the noun carries (`handoff_type`, `references`, `replaced_by` and the rest, sorted by key), so editing any field of a noun changes the file. Names: lower camel case of the noun's ASCII letter and digit runs, with a scope after `@` joined with `_` (`customer@finance` is `customer_finance`); two nouns with one name stop the generator. Every name, the `Level` and `Department` constructors included, is written in Lean's `«»` quotes (`«customer_finance»`), so a noun that is a Lean keyword (`sorry`, `syntax`) or starts with a digit still parses, with no keyword list. The quotes are not part of the name, so other files write `customer_finance`. The checks call `Decidable.decide` and `Option.some` by their full names, so a noun named `decide` or `some` cannot shadow them. An ontology with no nouns stops the generator with exit 2. `node schema/terms/gen-concepts.ts --check`, which `test.mjs` runs, fails when the file differs from a fresh run.
- [`Naive/StandingRules.lean`](./Naive/StandingRules.lean): Wilson lower bound for earning a standing rule, and the floored Wald SPRT for losing one. Each theorem is stated in plain language in [`STANDING_RULE_LEARNING_2026-11-02.md`](../docs/design/STANDING_RULE_LEARNING_2026-11-02.md).

Build: `cd lean && lake exe cache get && lake build` (toolchain pinned in `lean-toolchain`; install with elan). [`Naive/StandingRules.lean`](./Naive/StandingRules.lean) uses Mathlib for real square roots and logarithms, and `lakefile.toml` builds it as its own root (`Naive.StandingRules`) so Mathlib is not imported beside `Naive.Concept`. The other files stay in core Lean. `lake exe cache get` downloads Mathlib's build cache. CI does that and then `lake build`. The cache lives under `lean/.lake`, which `eslint.config.mjs` ignores.

The names here and the term engine are tied together by `node schema/terms/lean-agreement-test.ts`, which `test.mjs` runs. It fails, naming the theorem, when a term in `schema/terms/admitted.json` cites a theorem that no `.lean` file in `Naive/` declares. Declared means a line that starts with `theorem <name>` once Lean comments are removed. It also fails when a Lean concept has no admitted term. It reads every `.lean` file under `Naive/`, subfolders included. A Lean concept is a top-level `def` or `abbrev` whose declared type is `Concept <facts>`, named plainly or in `«»` quotes (the quotes are dropped from the name), so `founder`, `coFounder`, `thresholdGuardian` and `phaseGate` are concepts, and their admitted ids are their names in kebab case (`co-founder`). Helpers are told apart by type: fact structures, witnesses such as `jobs`, property pairs and functions are not of type `Concept`. A new concept therefore needs an admitted term in the same change. One file is exempt: `Naive/Generated/Ontology.lean`, because its concepts are ontology nouns, not glossary terms (EE-095), and `gen-concepts.ts --check` pins it to `docs/ontology.json`. Any other file, in `Generated/` or elsewhere, is held to the rule. `--root <dir>` checks one tree only. The test ties names, not meanings: the `lean` workflow builds the proofs, and it now runs when `schema/terms/` or `docs/ontology.json` changes as well as `lean/`.

Conventions follow spct-lean: every property is a check that can fail; the facts carry no label field, so no check can read one.
