# Schema index

The Everything Ecosystem is a schema, version in `VERSION`. An instance is a builder's workspace: a set of ventures, each with its product cards and, where it keeps them, account records (EE-011, EE-021). Personal life is out of scope (EE-009). This index lists every record type, so anyone can build an instance from this repo alone. Its machine form is `schema/data-model.json` (EE-018): every record type, its owning layer, schema, paths and references, checked by `schema/check-data-model.mjs`. There is no single master schema; the data model is the map of all of them. Nouns follow `docs/ontology.md` (EE-014).

Status:
- **defined**: a JSON Schema exists.
- **prose**: the shape is described only in Markdown.
- **missing**: the record type has no definition yet.

A model proposes a change only as a change line that fits its `change_line` definition: one verb (create, amend, delete), one kind of that verb, one noun and a tier (low, costly, one_way_door). derive names its `source` and merge its `successor`. The pattern ends with `$(?![\s\S])`, because Python's `$` also matches before a final newline, so `client\n` is rejected in Python and JavaScript alike. | Upper ontology | `docs/ontology.json`, `schema/terms/upper-test.ts`, `lean/Naive/Upper.lean` | defined | Naive's top categories (N-049, EE-113): information artifact, party, capacity, process and characteristic, each mapped to the class of BFO (ISO/IEC 21838-2) it falls under. Each noun names what it is a kind of in `broader`: another noun or a top category. `node schema/terms/upper-test.ts` runs the admitted term `top-category` (level hierarchy) on the whole hierarchy: no cycle, a top category has nothing broader, no orphan, and no noun reaches two top categories. It names each orphan, each noun under two top categories and each noun on a cycle, and a broader target that is not a live noun or a top category. Where both ends of a link name admitted terms at one level, the relation the engine read off their pass sets must be is_a or equal. Each top category's BFO class must be the label of its IRI in a fixed table of the five BFO classes used, and an unknown IRI or a mismatched label names the category. `lean/Naive/Upper.lean` proves that on any finite hierarchy no cycle, no orphan and no noun reaching two top categories give each noun exactly one top category (`upper_one_top_of_checks`). | Ontology catalog | `docs/ontology-catalog.json`, `schema/ontology-catalog.schema.json`, `schema/terms/catalog-test.ts` | defined | The catalog of ontologies (N-050): one file lists every `name@function` scope with its own version, owner, status (proposed, in-force or retired) and imports. The cycle verdict is the admitted term `layer`'s property L2 run on the scopes and their imports through the term engine. A cycle is printed in order. Every term a scope's nouns use through `broader` and `capabilities` must be defined in the scope or in one it imports directly, and a noun's `term` must be admitted in `schema/terms/admitted.json`. A missing term is never coined. It is printed as an open item for its owning scope: the scope that defines it, else the scope its `name@function` suffix names, else the scope that uses it. Every input (the catalog, `docs/ontology.json`, `schema/terms/admitted.json` and `operations/departments.json`) is parsed and its shape checked before any rule runs, so a missing or malformed file, or a scope with a missing field or one of the wrong type, prints `FAIL  the catalog cannot be checked: ...` and exits 1. `--root <dir>` checks one copy of the repository. | Glossary terms | `schema/terms/terms.ts`, `schema/terms/levels.ts`, `schema/terms/fixtures.ts`, `schema/terms/admit.ts`, `schema/terms/admitted.json`, `lean/Naive/` | defined | Every new or contested term is admitted by `node schema/terms/admit.ts` (EE-095): properties checked on facts, never on the label, frozen by hash, checked as a valid test and cross-run against every term at its level over seeded cases. Six levels: membership, relationship, encounter, arrangement, hierarchy and link. The link level holds the term typed-link: a graph of ideas and scopes whose links each name a relation from the closed set in `schema/terms/relations.ts`, which maps every relation to SKOS, PROV-O, DCMI Terms, AIF and IBIS. It fails on a name outside that set or on the wrong kind of target, a self link, a target that does not exist (a scope the idea creates may be new) and a cycle through broader (narrower read backwards), part-of or builds_on. `lean/Naive/Terms.lean` proves the relation table keeps reading narrower backwards sound. A check that calls a helper lists it in `uses`, so freezing hashes the helper's source too. A level may have fixtures, real cases each term is run on, recorded with the properties that failed and whether the expected result held. Arrangement has four: EE-001's seven groupings, the layer manifests as built, the OSI model and the ontology's three layers. Every term carries four labels (N-051 to N-055), typed as one union in `schema/terms/terms.ts` so an illegal pair does not type-check: scope (`shared`, or a `naive@<function>` scope listed in `docs/ontology-catalog.json`), origin (adopted, adapted, narrowed, broadened, borrowed or operationally coined; adopted carries the source's definition quoted), grade (standard, regulatory, codified, convention, seminal or none) and designation (term, proper-name or appellation; symbol is reserved). A proper name or an appellation names one referent and what it is an instance of. Labels sit on the term, not on the facts, and freezing ignores them. Admission checks them again at runtime, since a term run without type checking can break the type: an adopted origin with no quote fails, a scope not in the catalog fails, one proper name with two referents fails, and the 10 percent cap fails when more than a tenth of the terms with designation term are operationally coined or borrowed. The failure prints the share. Proper names and appellations are left out of both sides of the share. `lean/Naive/Terms.lean` proves that a proper name or an appellation never counts toward the cap and never changes its verdict, and that an adopted origin cannot be built without a non-empty quote. The labels on today's terms are proposed, like the terms. Not built: admission does not check that a named Lean theorem proves the current properties. `node schema/terms/bypass-guard-test.ts` keeps symbolic checks on the engine: every `schema/check-*` file and every `schema/` file whose name holds "gate" (ending .js, .mjs, .cjs, .ts, .mts or .cts) must be in its registry, and one that decides membership, relation or label must import `schema/terms/engine.ts` at runtime (directly or through a module it imports), run `schema/terms/admit.ts` (its path passed to spawn, execFile, fork or exec, or the file imported), or name a Lean theorem declared in `lean/Naive/`. Imports and admit paths are read from the code with comments and string contents removed, so a commented-out import or an error message that names admit.ts does not count, and a type-only import is erased at runtime and does not count either. A file outside `schema/` that decides a label may be registered too, and is then held to the same wiring: `scripts/reconcile-ideas.ts` is registered as symbolic. A file that decides none of these is registered as not symbolic with a reason. A symbolic file not wired yet is registered as unwired with a reason, printed on every run, and fails once it reaches the engine, so the list only shrinks. Today those are `schema/check-people.mjs` and `schema/check-governance.mjs`, which read who is a founder from a label (the role's `founder` flag and the holder's `kind`). The guard checks the wiring, not that the engine decides the verdict. `node schema/terms/lean-agreement-test.ts` keeps `schema/terms/admitted.json` and `lean/Naive/` in step: every Lean theorem a term cites must be declared there, and every top-level Lean definition of type `Concept` must have an admitted term (see `lean/README.md`), except in `lean/Naive/Generated/Ontology.lean`. `node schema/terms/gen-concepts.ts` writes that file, one Lean concept per noun in `docs/ontology.json`, each checking the noun's level and owning function, with every name in Lean's `«»` quotes so a noun that is a Lean keyword still parses and every field of the noun in its docstring; `--check` fails when the committed file differs from a fresh run, an ontology with no nouns exits 2, and `node schema/terms/gen-concepts-test.ts` regenerates it from fixtures, Lean keywords among them |

## Docs next to the code

Every README in this repo, this one included, and every playbook under `library/packages/*/playbooks/` is checked by `schema/check-docs-claims.mjs`: the paths, commands and routes it names must exist and its relative Markdown links, inline or reference-style, must resolve (HTML `href` and `src` are not checked). A pull request that changes code here, meaning any file that is not `.md` or `.mdx` and not under a `playbooks/` folder, owes this README an update, or a line in its body that starts with `No docs change: ` and gives a real reason (`.github/workflows/docs-required.yml`). New READMEs follow `docs/readme-template.md`.

## Open reconciliations

1. **Venture profile guidance.** The profile has no guidance of its own since the SAD documents were removed (EE-036); write a short template when a venture first needs one.
2. **MAD's tiers.** EE-013 renames MAD's four layers to tiers; the MAD repo and older method documents still say layers.
3. **Decisions.** The schema keeps its own log (EE-001 to EE-017). Older documents under `operations/` still cite workspace ids.
4. **Personal references.** About twelve files still name one person or their paths. They need to be made generic or moved out.
5. **Personal system.** Out of scope (EE-009). Built separately and joined later through links.
6. **Layer.** The term engine admits layer in its standard technical sense: a part of an arrangement whose dependencies hold no cycle and put every part in one stack, so each part depends only on the parts beneath it. Run on real arrangements, it passes the OSI model and the ontology's three layers (metamodel, upper ontology, catalog). It fails Naive's own groupings, both the seven EE-001 decided (their loop is a cycle) and the seven manifests as built (their reads form cycles, such as knowledge reading venture from system while system reads decision from knowledge). So for Naive's groupings "layer" works as the system's name for its parts, and the general word keeps its standard meaning with no definition of Naive's own. EE-013 ("layer means only the system's seven layers") and the `layer` noun in `docs/ontology.json` ("one of the six") are unchanged; reconciling them is Torian's call.
